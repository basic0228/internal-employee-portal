- Excel은 원본별 표를 유지하고 기록 조건·버전·묶음이 같은 두 실행의 기술 통계만 별도로 추가했다. 이전 타임아웃 2건은 설정·revision이 달라 이 묶음 통계에 합산하지 않았다. 전체 원본 건수 4는 목록 집계이며 동질한 성능 표본 수를 뜻하지 않는다.
- 성공 원본이 처음 추가되며 기존 Excel 오류 집계의 빈 문자열 처리 문제가 드러났다. numeric issue count를 사용하도록 수정하고 수식의 개수·비율을 각 원본 outcome과 대조했다. 최종 두 성공 행 error n=0/error rate=0, 앞선 timeout 행은 각각 error n=1이다. 수식 오류 검사 0건·후보 입력/원복 검증 통과. 기존 Vulkan 오류로 시각 검증은 미완료다.

API Reliability Lab의 핵심 도구를 2026-10-11 로컬에 구현했다. 구현 검증 시점에는 외부 API를 호출하지 않았다. 이후 첫 외부 GET 관측은 위 별도 절에 기록했다. LOCAL_MOCK 검증은 이 보고서의 외부 실측으로 사용하지 않는다. 실측 후 다음 항목을 기존 결과와 함께 내보낸다.

- runId·조건·코드/명세 버전·진행/중단 상태·시도/응답/미완료 n
- 백분위수 계산법(Type 7 구현), 통계별 분모, 타임아웃 표본의 중도절단 한계
- HTTP 지연과 업무 처리시간·발견 시간 구분
- Timeout/Retry/Polling/동시성 후보 비교 및 모델의 가정
- 선택값과 연결된 실행 ID·n·통계·이유·반대 장점·부적절한 상황
- 실제 재시도 실험이 없으면 Retry 성공률은 추가 실험 필요

설계 및 임시 보호 상한은 측정 결과가 아니다. 현재 운영 정책은 확정하지 않는다.

실행 준비·비활성 플래그·검증 범위는 [구현 안내](API_RELIABILITY_LAB_IMPLEMENTATION.md)를 참조한다. Markdown 다운로드를 검토해 승인된 EXTERNAL 실행만 이 문서에 반영한다. 화면 선택 Endpoint와 전체 Endpoint별 요약을 함께 기록한다. 기존 기록을 자동 삭제하거나 덮어쓰지 않는다.
# 새 케이스 계획과 자동 저장 구현 (외부 측정 전)

`LAB_CAMPAIGN_PLAN.md`에 GET 9조건 + POST/Polling + 중복 POST를 정의했다. 사용자 확정 기준은 **각 케이스의 모든 HTTP 요청 합계 100건**이며 업무 절차 100회가 아니다. 새 11조건의 외부 표본은 각각 n=0, 총 n=0이다. 과거 별도 GET 관측을 새 계획으로 자동 합산하지 않는다. 실제 호출 전 최종 계획 확인이 필요하다.

V4 SQL 및 opt-in `LAB_RECORDING_ENABLED`로 관리자별 계획·케이스·실행 관측을 서버 DB에 저장한다. 로컬 H2와 LOCAL_MOCK만으로 100건 예산/관측 저장/소유자 접근/연결 종료/불완전 POST·Polling을 검증했다. 브라우저 모의 GET n=1을 중단 후 새로고침하여 n=1, 미시행99 복구를 확인했다. 이는 API 성능 근거 표본이 아니다. 운영 PostgreSQL 적용·운영 저장 복구·실제 POST/Polling은 아직 미검증이다.
