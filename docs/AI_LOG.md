## B. 실제 AI 구현 오류와 수정

**재직 검사 경로 판별:** AI의 초기 EmploymentGuardFilter가 getServletPath()만으로 API를 판별해 servletPath가 빈 요청에서 검사를 생략했다. MockMvc의 퇴사 세션·재직 상태 변경 테스트2개가401 대신200으로 실패했다(당시14개 중2개). PathPatternRequestMatcher로 수정한 뒤 당시18개 테스트가 통과했다. 이후 확대 검증은 별도 시점으로 기록하며 운영 PostgreSQL 검증으로 대체하지 않는다. 코드: `backend/src/main/java/com/bit/portal/auth/EmploymentGuardFilter.java`. 상세 재현·검증은 [작업 기록](AI_LOG_HISTORY.md)에 있다.

**측정 해석 수정:** 중단 경과10003.931728ms는 완료 응답 지연이 아니므로 후보10001ms를 초과한 성공으로 분류할 수 없음을 확인했다. 후보 비교에서 중단을 미확정으로 처리하고 실제 원본 기반 회귀 테스트를 추가했다. 당시 프론트8개가 통과했다. 모의 회귀 검증을 새 외부 표본으로 세지 않았다.

**이번 Excel 내보내기 오류:** AI가 UTC ISO 문자열을 그대로 셀에 쓴 첫 통합본에서 내보내기 도구가 날짜로 자동 변환해 소수점 정밀도를 줄였다. 저장된 XLSX의 XML과 원본 시각을 비교하다 발견했다. `UTC ` 접두사를 붙여 원문 시각을 보존하도록 수정하고 65건의 시작·종료 시각과 지연을 다시 대조해 통과했다. 원본 JSON은 바꾸지 않았다.

**업무 이력 갱신 오류(2026-10-12):** 최초 구현에서 DB 갱신 권한의 lease 시각을 Java 나노초 정밀도로 만들었지만 DB는 마이크로초로 저장했다. 정상DETAIL 후clear 갱신과 오류 후poll_stopped 갱신을 검증하는 두 테스트가 실패했다. lease 시각을 마이크로초로 맞춰 조건부 UPDATE가 일치하도록 수정했다. 별도로 모의 HTTP 테스트의150ms 제한이 정상 생성까지 중단시키는 문제는 로컬 제한을1초, 의도적 응답 유실 지연을1.5초로 구분해 수정했다. 최종 전체95개 테스트가 통과했다. 운영 timeout 기본값30초는 이 모의 시간 조정으로 바꾸지 않았다.

## 검증·협업 범위

관리자 직접 계정 생성, 연락처만 수정, 세션+CSRF, 퇴사자 기존 세션 재직 확인, PrimeVue4.5.5는 사용자 선택을 코드에 반영했다. API Reliability Lab은 공통 Client·서버 호출·관리자 전용·호출 상한·실측 저장·후속 프로토콜로 확장했다. 실측 고유39run/65시도, pending→최종 발견 n=0, 실제 추가 retry1건/회복0건을 보존했다. 미시행을 가상 표본으로 채우지 않았다.

이번 통합은 문서·오프라인 분석·Excel만 변경했다. 운영 키·설정·DB·외부 부하는 변경하지 않았다. runId/attemptId로 중복을 제거하고 계획과 run을 대조했다. Excel 후보 변경·원복, 수식 오류0, 원본65행 일치, 전체 source SHA256 대조를 검증했다. 대체 레이아웃5시트/7영역을 검토해 표시 잘림0건을 확인했다. native 렌더러 Vulkan 오류로 실제 Excel 시각 검증은 미완료다.
