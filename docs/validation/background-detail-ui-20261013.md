# 배경 조회 상세 UI 확인 — 2026-10-13

## 문제와 확인 결과

사용자는 배경 조회에서 이력만 보이고 상세 내용이 없다고 보고했다. 기존 구현은 이력 마지막 열의 ‘결과 확인’을 누른 경우에만 수동 상세 GET을 실행했고, 상세 응답이 있을 때만 이력 아래에 상세 영역을 만들었다. 좁은 모달과 긴 표에서 버튼·결과를 찾기 어려웠으며, 미선택 상태와 상세 조회 실패 모두 빈 화면처럼 보일 수 있었다.

배포 페이지에서 EMP-001의 기존 완료 이력 한 건을 수동으로 열었다. 상세 응답은 받지 못했고, UI에 실패 안내 및 열람 결과 `UNCONFIRMED`가 표시됐다. 이번 응답의 정확한 외부 HTTP 코드·실패 원인은 당시 화면만으로 확인하지 못했다. 특정500이나 timeout으로 단정하지 않는다. 신규 외부 POST는 이 점검에서 실행하지 않았다. 모달에 있던 기존 pending의 자동 관찰은 수동 검증과 별개이며, 그 HTTP 수를 별도로 계측하지 않아 Lab 표본에 합산하지 않는다.

## 수정

- 이력의 상세 버튼을 첫 열로 옮기고 ‘상세 결과 보기’로 명확하게 표시했다.
- 상세 영역을 모달 위쪽에 항상 표시한다. 선택 전 안내, 조회 중, 조회 실패, 반환된 상세 결과를 구분한다.
- 선택한 조회 번호·요청 시각을 상세 영역에 표시하고 수동 선택 시 해당 영역으로 이동한다.
- 다른 확인 작업이나 서버의 호출 대기 제한에는 직접 재열람해야 함을 안내한다. 대기 시각은 한국 시각으로 표시하며 클라이언트 표시만으로 서버 제한을 우회하지 않는다.
- 최근 확인 HTTP 오류·요청 timeout을 이력에서 보여 준다. 저장된 최근 관측을 이번 호출의 원인으로 단정하지 않는다.
- pending·누락 결과를 범죄 이력 없음 또는 검증 완료로 표시하지 않는다. 상세 내용의 DB 저장·자동 재시도·새 조회 POST·외부 정책 변경은 추가하지 않았다.

변경 코드: `frontend/src/components/BackgroundCheckDialog.vue`, `frontend/src/PortalApp.vue`, `frontend/src/portal.css`.

## 실제 검증

포털 활성화 빌드(`VITE_PORTAL_UI_ENABLED=true`)가 통과했다. 기존 번들 크기 경고는 남아 있다. 로컬 미리보기는 127.0.0.1의 H2 메모리 DB와 모의 API를 사용했으며 운영 DB나 실제 외부 API를 사용하지 않았다.

| 확인 | 결과 |
|---|---|
| 이력 미선택 | ‘조회 상세’ 영역과 버튼 선택 안내 표시 |
| 신규 모의 조회·자동 상태 확인 | 이력이 생성·갱신되어도 상세 내용은 자동 노출되지 않음 |
| 수동 모의 상세 조회 | 선택한 조회 번호, clear 상태, 완료 시각 및 결과 항목 표시; 결과 영역으로 이동 |
| 모의 응답의 누락 필드 | 범죄 이력은 ‘미확인’, 학력·경력·신용은 ‘결과 없음’; 임의 값 생성 없음 |
| 자동 확인 직후 수동 열람 | 상세가 없으면 실패·대기 안내가 보임 |
| 수동 상세 직후 연속 클릭 | 서버 대기 제한과 다음 확인 시각 안내 표시; 자동 재시도 없음 |
| 대기 후 직접 재열람 | 상세 표시와 수동 열람 이력 확인 |

UI 검증용 모의 결과는 API 실측 및 MEASUREMENTS 통계에 추가하지 않는다. 로딩 안내는 구현했으나 빠른 모의 응답에서 지속 표시 시간을 별도로 검증하지 않았다. 이 문서 작성 시 수정 후 운영 UI 확인은 배포 뒤 남아 있었다.

로컬 화면 증거는 Git 제외 경로 `outputs/deploy/background-detail-local-success-20261013.png` 및 `background-detail-local-wait-20261013.png`에 저장했다. 수정 전 운영 미확인 화면은 `background-detail-production-unconfirmed-20261013.png`다. 상세 화면 증거를 API 키나 실제 개인정보를 포함한 일반 운영 로그로 저장하지 않는다.
