## 수학·통계·공학 모델

Timeout은 완료 정상 ECDF에서 후보를 초과한 수/n을 재분류한다. 중단 응답은 미확정이며 새 제한의 성공률로 예측하지 않는다. LIST와 DETAIL을 분리한다. p99는 Type7이며 소표본 최상위 값에 민감하다. 독립 동일분포를 가정한 수학 예시에서 참 p99 초과 값을 한 번 이상 볼 확률은 `1−0.99^n`이다. n=100은 약63.4%이며 실제 중단 의존 표본의 신뢰수준이나 필요한 호출 수를 의미하지 않는다.

추가 retry R, 요청 전체 제한 T, 대기 bᵢ, 안내 hᵢ이면 `W=(R+1)T+Σmax(bᵢ,hᵢ)`다. Exponential은 `bᵢ=min(cap,b×2^(i−1))`이다. 다음은 T=30초, b=1초, cap=4초를 가정한 **공학 모형**으로 회복률 실측이 아니다. 큐·저장 여유는 별도다. connect 제한은 T 안의 제한이며 T와 더하지 않는다.

| 추가 R | 안내 없는 Fixed 상한 | 안내 없는 Exponential 상한 | 모든 대기에 h=30초를 가정한 상한 |
|---:|---:|---:|---:|
| 0 | 30초 | 30초 | 30초 |
| 1 | 61초 | 61초 | 90초 |
| 2 | 92초 | 93초 | 150초 |

D=120초 예산이면150초를 모두 실행할 수 없다. 다음 요청의 전체 제한을 확보하지 못하면 추가 요청을 시작하지 않는다. Fixed/Exponential 성공률·우열은 실제 대조가 없어 계산하지 않는다.

Polling의 이상적 발견 모델은 GET 시간0/실패 없음 가정에서 `ceil(d/P)`회, 발견 지연 `ceil(d/P)P−d`다. 실제 구현은 응답 후 P를 기다리므로 요청 시간이 추가된다. 업무 d가 미관측(n=0)이어서 예상 조회 수·발견 지연은 추가 실험이 필요하다. 최악 자원 상한 `Tpost+K(P+Tget)`과 전체 deadline을 구분한다.

동시성은 응답시간·오류율·처리량을 같은 조건에서 비교해야 한다. Little 법칙 `L=λW`는 안정 상태와 일관된 측정 경계가 필요하다. 현재 중단·휴지기가 있는 탐색 run의 처리량만으로 안전 동시성을 역산하지 않는다. 시간 순서의 혼란변수와 이미 시작한 묶음의 회수 표본을 보존한다.

## 코드 반영 경계

2026-10-12 사용자 요청으로 업무 POST·이력 저장과 보수적 초기 설정을 구현했다. 적용 기본값은 연결5초/전체30초, 추가 GETretry0, POSTretry0, 폴링5초/120초/24회, 업무 인스턴스당 동시1이다. 위 표의 TODO는 실측 최적값 확정을 뜻하며 **코드 설정이 없다는 의미가 아니다.** 초기값·재검토 이유·운영 적용은 [BACKGROUND_CHECK_POLICY](BACKGROUND_CHECK_POLICY.md)에 분리했다. POST 응답 유실 복구 외부n=0, Lab 최종 발견0, 후속 업무 수동 발견1·자동 발견0, 정확한 서버 업무 시간0, 재조회 유효기간 근거 없음은 유지한다.

- 업무 GET 설정: `background-check.client.connect-timeout-ms`/`request-timeout-ms`, 환경변수 `BG_CONNECT_TIMEOUT_MS`/`BG_REQUEST_TIMEOUT_MS`. 전체 요청 제한이며 별도 socket read-timeout이 아니다.
- Lab은 같은 Client에 승인된 실험 값을 요청별로 전달한다. Lab retry·polling이 업무 자동 정책을 적용했다는 뜻은 아니다.
- 업무 정책은 실제 설정 바인딩과 서버 검사로 연결했다. 기본retry0, 활성화 시GET500/503에Fixed대기·추가 최대1회를 지원한다. POST는 설정에 관계없이 재시도하지 않는다. 폴링은 서버가 간격·마감·횟수를 검사하고 관리자 화면에서 후속 확인을 요청한다. Lab 후보 출력은 계속DRAFT이며 자동으로 업무 설정을 적용하지 않는다.
- 현재 실험은503/429/대기 안내/timeout/네트워크·계약·저장 오류에서 후속 묶음을 차단한다. C03의 정상 형식500 계속 수집은 승인된 비교 예외다. 업무의오류·최종 상태·시간/횟수 초과·모달 닫기·로그아웃 중단은 구현했고, 운영 예외 효과·최적값은 TODO다.

추가 실험은 잔여 예산을 자동 소진하지 않는다. [후속 계획](LAB_FOLLOWUP_TEST_PLAN.md)의 선행 조건을 지킨다. 최종 판단은 [DECISIONS](DECISIONS.md)에 사용자 확인 후 반영한다.
