## 근거자료 통합 결과

원본의 runId/attemptId를 중복 제거해 고유39실행/실제65시도를 확인했다. 초기11조건은15실행/34시도/POST6, 승인 후속은13실행/18시도/POST2, 별도 탐색은11실행/13시도/POST0이다. 완료 HTTP55건, timeout8·취소2건이다. 이 합계는 기록 재고이며 단일 지연·오류 확률 추정이 아니다.

필수 DETAIL 정상200 n=2의 p50=325.184/p95=332.955/p99=333.645/최대333.818ms다. 별도DETAIL500 n=1과DETAILtimeout n=2를 분리했다. 소표본 p99는 장기tail 보장이 아니다. 반복POST 비교2쌍 모두 다른ID, 이력 대조는1쌍 성공했다. POST8건 중 초기clear4·pending4이며 pending→최종 발견n=0, 정확한 업무시간n=0이다. 실제retry1건은503→30초 안내 대기→500으로 회복0/1이었다.

## 검증과 부록

**업무 배경 조회 로컬 검증(2026-10-12):** Java21/H2/루프백 모의 API로 최종 백엔드95개 통과. 신규 업무 이력13개와 공통 Client 서비스6개를 포함한다. 프론트는 기존Lab21개와 업무 상태2개, 총23개 통과. 관리자UI opt-in 빌드와 Spring Boot JAR 패키징 통과이며 번들 크기 경고가 남는다. 기존 실측 원본과 통합 Excel은 변경하지 않았다.

**후속 배포 확인(2026-10-12):** `d143d79`와 문서 커밋 `e197845`의 Railway success, 최신 UI 번들 일치와 공개 health/DB health HTTP200/UP를 확인했다. 이후 사용자가 V5 생성과 앱 변수 설정·배포를 완료했다. [운영 적용 절차와 상태](BACKGROUND_CHECK_POLICY.md#운영-적용-및-검증)를 참고한다.

**관리자 운영 정상 경로:** 설정 반영 후 신규 버튼 활성화를 확인하고 승인된 EMP-001 업무POST1건을 실행했다. 즉시clear/이력1건을 확인했고 수동DETAIL GET1건 후 상세 화면·admin의DETAIL/HTTP_RESPONSE 열람 기록을 확인했다. 재열기 후 이력은 유지되고 상세는 초기화됐다. 비로그인 이력 API는401이었다. 외부 추가 호출은2건, 자동GET·retry는0건이다. pending 전환·응답 유실·USER403은 운영 미검증이다.
